# apps/mobile — Hermes Mobile (Android)

Capacitor app that connects a phone to a Hermes Agent running elsewhere. Read
`README.md` for what it does and `PLAN.md` for why it is shaped this way; this
file is only the rules for editing it.

## The one architectural rule

**The shell navigates the WebView to the user's own dashboard origin; it never
proxies, embeds, or holds credentials for it.** Consequences to respect:

- The Capacitor bridge exists **only** on the bundled shell origin. Any feature
  that must work while the user is inside their dashboard (back navigation,
  downloads, cookie persistence, notifications) has to be implemented natively in
  `android/app/src/main/java/…`, not in TypeScript.
- Nothing in `src/` may store a password, token, or API key. `lib/storage.ts`
  holds the saved server list and two preferences, and that is the whole budget.
- Do not add CORS headers, an API-base override, or a token-injection path to
  `web/` or `hermes_cli/web_routers/` on this app's behalf. Phase 3 (a native
  chat client) is the sanctioned route to a non-same-origin client, and the
  backend already supports it — see `PLAN.md` § The premise.

## Layout

```
apps/mobile/
├── src/lib/          # platform-independent logic + colocated *.test.ts
├── src/app/          # screens and components (thin; no business logic)
├── src/App.tsx       # the three-screen state machine
├── android/          # generated by `npx cap add android`, then customized
│   └── app/src/main/java/com/nousresearch/hermes/mobile/
│       ├── MainActivity.java        # back nav, downloads, cookie flush
│       └── HermesShellPlugin.java   # keep-awake, per-origin sign-out, version
├── capacitor.config.ts
└── PLAN.md
```

`android/` is committed (Capacitor convention, and `MainActivity.java` /
`HermesShellPlugin.java` are hand-written). Its own `.gitignore` excludes build
outputs, `local.properties`, and the generated `app/src/main/assets/public` +
`capacitor.config.json` — those come from `npm run cap:sync`. Never commit them,
and never edit `capacitor.settings.gradle` / `app/capacitor.build.gradle`
(regenerated by `cap sync`).

## Conventions

- **New behaviour goes in `src/lib/` with a colocated test.** The screens stay
  thin enough to review by eye; the URL gate, status parsing and the saved-server
  list are the parts that must not regress. `npm run check` runs typecheck +
  vitest + eslint.
- **Shared ESLint config**: `eslint.config.mjs` spreads `../../eslint.config.shared.mjs`,
  so import/export sorting and `type-imports` are enforced — run `npm run fix`.
- **Dependencies**: match versions already in the root lockfile where a package
  is shared (React, Vite, Tailwind, TypeScript), and mind the root `.npmrc`
  `min-release-age=14` — a version published in the last fortnight will not
  install. Capacitor packages must stay on one major (currently 8.x).
- **Adding a workspace dep changes the root `package-lock.json`.** Keep that diff
  additive: `npm install --workspace apps/mobile --include-workspace-root=false`,
  then check `git diff --stat package-lock.json` for churn in unrelated entries.
- **Native edits are unverifiable without an SDK.** Say so in the PR body; CI
  (`ci/mobile-android.yml` + `ci/mobile-release.yml`, staged — `git mv` them
  into `.github/workflows/` to activate) is the first real compile.

## Security notes for reviewers

- `network_security_config.xml` is TLS-only in release builds, cleartext only for
  on-device hosts (`127.0.0.1`, `localhost`, `10.0.2.2`). The debug manifest
  overlay additionally allows LAN `http://`. Do not widen the release config to
  make a demo easier.
- `server.allowNavigation: ['*']` is a known trade-off (a saved address is
  runtime data). Replacing it with a per-server mask is Phase 2.2 — do not add
  more wildcard surface in the meantime.
- Sign-out clears cookies for one origin at a time
  (`HermesShellPlugin.clearSiteData`). A "clear everything" WebView API would
  also drop the shell's own localStorage; keep it per-origin.
